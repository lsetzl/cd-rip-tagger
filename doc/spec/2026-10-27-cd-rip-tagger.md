# cd-rip-tagger：CDと商品ページURLから取り込み・エンコード・タグ付けまで行うスキル

- 作成日: 2026-10-27
- 元チャット: claude.ai チャット「CD音楽DB/同人CDのタグ付け」

## 目的
CDをドライブに入れた状態でBOOTHなどの商品ページURLを渡すと、リッピング・MP3エンコード・タグ付け・ライブラリへの配置までを一括で行う Claude Code スキルを作る。

## 背景
最近購入した同人CD（オリジナル系）が gnudb / MusicBrainz / CTDB のいずれにも未登録で、取り込み時にタグが取れない。曲目は商品ページ（BOOTH等）に載っているので、それを元にタグを付ける作業を自動化したい。

## 決定事項
- GitHub の新規リポジトリ `cd-rip-tagger` として作る
- 入力は「ドライブに挿入済みのCD」＋「商品ページのURL（BOOTH等）」
- リッピング・エンコード・タグ付けを一括で行う。リッパーはコマンドライン型のものを使う
- 出力形式は MP3 のみ
- 出力先は `<ライブラリルート>/<アーティスト名>/<アルバム名>/`。ライブラリルートはユーザーに入力させる
- MusicBrainz への登録は今回は行わない
- 基本は自分用だが、配布もできる形にする。ユーザーごとに変わりそうなライブラリルートとエンコード設定は、後から変更できるのが望ましい（最悪スキルを直接書き換える形でも可）
- 初回実行時にライブラリルートとエンコード品質をユーザーに聞く
- ユーザー確認は1回にまとめる。CDのトラック数とページの曲数が合わない場合も、この確認の中でユーザーに判断してもらう
- 日本語タグの文字化けは、一般的に化けにくい方式を採用することで対応する。プレイヤーごとの検証は求めない

## 受け入れ条件
- [x] CDを入れた状態でURLを渡すと、確認を1回挟んで、取り込みからタグ付け・配置まで完了する
- [x] 確認時に、抽出したタグ一覧・出力先パス・注意事項（トラック数の不一致など）が提示され、ユーザーが修正を指示できる
- [x] 出力先が `<ライブラリルート>/<アーティスト名>/<アルバム名>/` になる
- [x] タグとして、アルバム名・アルバムアーティスト・曲名・トラック番号・曲ごとのアーティスト・年・ジャケット画像が入る（ページに情報がある範囲で）
- [x] 初回実行時にライブラリルートとエンコード品質を聞いて保存し、2回目以降は聞かない
- [x] ライブラリルートとエンコード設定を、後から変更できる
- [x] フォルダ名・ファイル名に使えない文字が自動で置き換えられる

全項目を実機で確認済み（2026-10-27）。商品ページ `https://serious-sentimental6.netlify.app/` と
4トラックのCDで、ページ読み取り→確認1回→取り込み→配置までを通した。ジャケット画像は埋め込んだ
`APIC` が元画像とバイト単位で一致し、ボーカル名の日本語は ID3v2.3 + UTF-16 で往復し、各トラックの
長さはCD上の値と0.05秒以内で一致した。使えない文字の置換は、記号を含む検証用データで別途確認した。

## やらないこと
- MusicBrainz への登録（今回は対象外。将来の拡張候補）
- MP3以外の形式での出力（自分用は MP3 で足りる）
- gnudb / Gracenote を使った曲名取得（新しい同人CDは未登録が多く、送信手段も細っている。Gracenote 系ソフトは手元のPCでドライブを認識しなかった）

## 確定事項（2026-10-27 にユーザー確認済み）
| ID | 内容 | 確定内容 |
|----|------|----------|
| A-01 | リッパー | cyanrip（Windows ビルド `cyanrip-win64.exe`） |
| A-02 | 取り込み・エンコード・タグ付けの経路 | cyanrip `-N -o wav` で**WAVとして取り込み** → ffmpeg(libmp3lame) でMP3へ → mutagen でタグ書き込み。cyanrip の `-o mp3` は品質指定が `-b <kbps>` のみで VBR V0/V2 を指定できないため採用しない。cyanrip の `-a`/`-t` も曲名の `:`/`=` が壊れる懸念があるため使わない |
| A-03 | フォルダ名の「アーティスト名」 | アルバムアーティスト（サークル名） |
| A-04 | ファイル名 | `NN 曲名.mp3`（NNは2桁ゼロ埋め） |
| A-05 | 文字化け対策 | ID3v2.3＋UTF-16。ID3v1 は書かない |
| A-06 | 設定ファイル | `%APPDATA%\cd-rip-tagger\config.json` |
| A-07 | エンコード品質 | VBR V0 / VBR V2（推奨・初期値）/ CBR 320kbps の3択 |
| A-08 | ジャケット画像 | 商品ページのメイン画像をMP3に埋め込む。`folder.jpg` は置かない |
| A-09 | 使えない文字の置き換え | `\ / : * ? " < > |` を全角の同等文字に置換し、末尾のドット・空白を除去。Windows 予約名は先頭に `_` を付ける |
| A-10 | ドライブの指定 | 光学ドライブを自動検出し、複数あればユーザーに確認 |
| A-11 | 対応するページ | BOOTH を主対象とし、それ以外もベストエフォートで抽出 |
| A-12 | 複数枚組のCD | 対象外（1枚ずつ処理） |
| A-13 | 依存ツールの導入 | cyanrip・ffmpeg・mutagen は、**何をどこから取得するかを提示してユーザーの承認を得た上で自動取得**する。置き場は `%LOCALAPPDATA%\cd-rip-tagger\bin`。Python 本体は自動取得せず案内のみ |
| A-14 | 「年」タグの値 | ページに記載された頒布日・発売日の年。無ければ空欄 |

仮置きは全て確定したため、コード中に `ASSUMPTION A-xx` コメントは残していない。

## 実機検証で判明したこと（2026-10-27）
- **トラック情報の取得は `.cda` スタブから行う**: Windows がシェル上に見せる `Track01.cda`（44バイトの RIFF CDDA ヘッダ）にトラック番号と長さ（フレーム数）が入っている。ファイルシステム層の読み取りなので生アクセスもリッパーも不要で、リモートデスクトップ接続でも動く。`cyanrip -I` はコンソールセッションなら正しく読めるが、確認画面に必要な情報が生アクセスなしで揃うこちらを主経路とし、cyanrip はフォールバックに回した
- **音声の取り込みにはコンソールセッションが必要（管理者権限は不要）**: 光学ドライブへの生アクセスはコンソールセッションに割り当てられる。実測では、リモートデスクトップセッションの非管理者は `CreateFileW` が `ERROR_ACCESS_DENIED`、同じRDPで管理者なら成功、**コンソールセッションなら非管理者でも成功**し、cyanrip も問題なくディスクを読めた。したがって要件は「コンソールで実行する」であり、リモートから使いたい場合の回避策として管理者権限がある
- **可否は推測せず実際に試して判定する**: 権限レベルやセッション種別から推測するのではなく、`CreateFileW` でデバイスを開いて即閉じることで判定する（`check-deps` の `can_rip`）。管理者権限・コンソールセッション・デバイスのDACLのどれで許可されていても同じように通るため、判定条件を増やさずに済む
- **前提は手順1で判定して止める**: ページの抽出や確認画面まで進めてから落とすと、ユーザーの作業が無駄になる。`check-deps` の時点で `can_rip` を確かめる
- **権限昇格はスキル側で行わない**: `Start-Process -Verb RunAs` による自己昇格は、昇格をスクリプトの内側に隠すことになり、非対話実行では応答できず、配布物としても不信感を与えるため採用しない
- **非昇格でCDDAを読む道の調査結果**: 当初「Windows Media Player や EAC は DirectShow の CDDA リーダーフィルタ経由でカーネルに読ませている」と推測したが、これは誤り。Windows は生CD音声用の DirectShow ソースフィルタを標準出荷しておらず、`CDDAReader.ax` は Guliverkli2 由来のサードパーティ製である。実際の制御機構はデバイスのDACLとローカルセキュリティポリシー（`AllocateCDRoms`）で、本機では未設定だった
- **cyanrip のリリース版とドキュメントの差が3件あった**: GitHub の README は master のもので、リリース版 0.9.3 とは中身が違う。実バイナリに聞いて判定する方針にした
  - `-B`（AcoustID 無効化）が存在しない → `-h` の出力からフラグの有無を判定する
  - 出力形式に `wav` と `pcm` が無い（flac / tta / opus / aac / wavpack / alac / mp3 / vorbis / aac_mp4 / opus_mp4 のみ） → `-o help` から対応形式を読み、可逆圧縮のものを優先順で選ぶ（実機では flac）
  - README に「default: 0」と書かれている `-s`（ドライブオフセット）が、実リップ時には省略できず `Offset is unset!` で停止する（`-I` では不要） → 常に明示的に渡す。値は設定可能にした（既定0）
- **エラー時は外部コマンドの出力を捨てない**: 当初 `rip_tracks` は失敗を一律「生アクセスが拒否された」と報告していたため、`Invalid format "wav"` という真因が隠れて診断が2往復余計にかかった。cyanrip の出力を控えて失敗時に提示し、アクセス拒否のヒントは実際にその兆候があるときだけ付ける
- **実機での一気通貫を確認済み**: 4トラックのCDで、リップ→flac中間→MP3(VBR V2, 191〜202kbps)→タグ書き込み→配置まで成功。ID3v2.3 + UTF-16、ID3v1 なし、曲名・アルバム名・アーティストの日本語と `:` `/` `<>` がタグ内で原文のまま往復し、ファイル名側では全角に置換されることを確認した。長さはCD上の値と0.05秒以内で一致。一時ファイルは削除される

## 実装で追加した決定
- **トラックの読み替え**: アルバム情報JSONの各トラックに `source_track`（CD上のトラック番号）を指定できる。CDのトラック数とページの曲数が合わない場合、確認時にユーザーの指示を受けてこれで対応付ける
- **既存ファイルの扱い**: 出力先に同名ファイルがあれば確認画面で警告し、`run --overwrite` が無ければ実行を拒否する
- **出力エンコーディング**: スクリプトの標準出力・標準エラー出力は UTF-8 に固定する（Windows の既定コードページでは日本語や全角記号が出力できず落ちるため）
- **アーティストタグの穴埋め**: 曲ごとのアーティストがページに無い場合は、アルバムアーティストで TPE1 を埋める（空欄だと表示が崩れるプレイヤーがあるため）。確認画面で対象トラックを提示する

## 技術的な制約・前提
- Windows ネイティブ側の Claude Code（PowerShell）で動かす前提とする。WSL2 からは光学ドライブが通常は見えないため
- cyanrip は Windows ではドライブレターを `-d` で指定する必要がある（既定値の `/dev/sr0` は Linux 用）
- `cyanrip -I` で、取り込まずにCDの情報（トラック数・各トラックの長さなど）だけを取得できる
- 商品ページの曲目は自由記述で書式がばらばらなので、決め打ちのパーサーではなく Claude がページを読んで抽出する。スクリプトは、抽出結果（JSON）を受け取って取り込み・タグ付け・配置を行う部分を担う
- 配布は `npx skills add <リポジトリURL>` で入れられる形（リポジトリ内に `SKILL.md` とスクリプトを置く構成）を想定する
- 対象の同人CDは gnudb / MusicBrainz / CTDB に未登録であることが多いため、外部DBからのメタデータ取得には頼らない
